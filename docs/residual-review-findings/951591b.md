## Accepted residuals

### R-RESIDUAL-1 — Device flow has no automated coverage (P1, testing)

The repo's only harness (`smoke_test.py`) is offline config introspection. It asserts the
control's markup, the hide rule, the injected script's markers, and the wiring, but it cannot
exercise device enumeration, the `getUserMedia` device pin, the missing-device fallback, the
permission hint, or hot-plug refresh. A regression in that JavaScript would still pass the
smoke test.

Verification is manual/in-browser per the plan's Verification Contract (AE1–AE7), ideally via
`ce-test-browser`. Adding a browser harness is outside this plan's scope.

### R-RESIDUAL-2 — Unsupported native-method override (P2, advisory)

The page script monkey-patches `navigator.mediaDevices.getUserMedia`. It only rewrites
audio-only requests and preserves other constraints, but it applies to every audio-only
request on the page, and it depends on FastRTC calling `getUserMedia` per recording start
(pinned to `fastrtc==0.0.34`). A dependency bump or another script replacing the method can
silently disable device selection.

### R-RESIDUAL-3 — Dependency and DOM/head assumptions (P2, advisory)

The hide rule targets FastRTC 0.0.34 DOM (`button[aria-label='select input source']`,
`.select-wrap`), and script injection relies on Gradio 5.50's `head` handling. A bump to
either can silently break the feature or make `head` a no-op. No test covers either.

### R-RESIDUAL-4 — CSP / iframe behavior unverified (P3, advisory)

Whether the deployed Space applies a CSP or iframe sandbox that suppresses the inline `head`
script was not verified here. A block would disable the feature with no Python-side symptom.
